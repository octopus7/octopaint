# OctoPaint 파일 저장 및 교환 형식 설계

이 문서는 OctoPaint의 영구 저장 경계와 외부 형식 호환 정책을 정의한다. 애플리케이션 계층은 `Open`, `Save`, `SaveAs`, `Import`, `Export` 유스케이스만 알고, 실제 코덱은 포트 뒤의 어댑터로 둔다. 따라서 WinUI 3 프런트엔드를 교체해도 문서 모델과 파일 형식은 바뀌지 않는다.

## 설계 원칙

- 편집 가능한 원본은 `.ocp`이다. 레이어, 그룹, 마스크, 채널, 조정, 선택 영역과 비파괴 상태를 모두 보존한다.
- PNG/JPEG는 교환용 단일 이미지이며, PSD는 최대한 편집 가능하게 교환하는 형식이다. PSD 왕복이 OctoPaint 원본 보존을 대신하지 않는다.
- 파일 읽기는 신뢰할 수 없는 입력 처리로 간주한다. 파서가 UI, GPU 리소스 또는 현재 문서를 직접 변경하지 못하게 한다.
- 저장은 특정 문서의 불변 스냅샷을 대상으로 한다. 저장 중 편집이 계속되면 저장된 리비전만 clean 처리하고 이후 편집은 dirty 상태로 남긴다.
- 다중 문서 편집기는 문서마다 독립적인 ID, 파일 경로, 리비전, dirty 상태와 저장 작업을 가진다. 하나의 `.ocp`에 여러 열린 문서를 묶지 않는다.
- 코덱 API와 디스크 스키마에서는 WinRT, HWND, Direct3D 타입을 노출하지 않는다.

## 코덱 경계

코어가 사용하는 논리 인터페이스는 다음 책임으로 분리한다.

```text
DocumentRepository
├─ Open(path, limits) -> DocumentSnapshot
├─ Save(snapshot, path, options) -> SaveReceipt
└─ Probe(path) -> FormatIdentity

ImportCodec
└─ Decode(stream, limits, cancellation) -> ImportResult

ExportCodec
└─ Encode(snapshot, stream, options, cancellation) -> ExportReport
```

- 파일 확장자가 아니라 매직 바이트를 우선 검사한다. 확장자와 실제 형식이 다르면 사용자에게 알리되, 검증된 형식으로 열 수 있다.
- `ImportResult`는 완성된 후보 문서와 경고 목록을 반환한다. 모든 검증이 끝난 뒤에만 작업 공간에 게시한다.
- `ExportReport`는 손실 항목, 병합 또는 래스터화한 노드, 색 변환과 제외된 메타데이터를 구조화해 반환한다. UI는 저장 전에 이 보고서의 요약을 보여줄 수 있어야 한다.
- 경로, 스트림, 진행률 및 취소는 애플리케이션 계층이 소유한다. 코덱은 대화상자를 띄우지 않는다.

## `.ocp` 네이티브 형식

### 컨테이너

`.ocp`는 ZIP64 컨테이너다. ZIP을 선택하는 이유는 스트리밍 작성, 알려진 복구 도구, 개별 엔트리 접근과 확장성 때문이다. 픽셀 타일은 자체 압축하므로 ZIP 엔트리 수준에서는 `STORE`를 사용한다. 작은 CBOR/JSON 엔트리만 `DEFLATE`할 수 있다.

컨테이너의 첫 엔트리는 압축하지 않은 `mimetype`이며 내용은 정확히 다음 ASCII 문자열이다.

```text
application/vnd.octopaint.document+zip
```

필수 및 선택 레이아웃은 다음과 같다.

```text
mimetype                         필수, 형식 식별자
manifest.cbor                    필수, 루트와 버전/기능 선언
integrity.cbor                   필수, 엔트리 크기와 SHA-256
document/document.cbor           필수, 캔버스/색/루트 노드
objects/<uuid>.cbor              필수, 레이어·그룹·마스크·조정·채널 객체
tiles/sha256/<hh>/<digest>.tile  필요 시, 내용 주소형 픽셀 타일
profiles/<digest>.icc            필요 시, ICC 프로파일
previews/composite.webp          선택, 빠른 파일 미리보기
previews/thumbnail.webp          선택, 셸용 작은 미리보기
metadata/user.json               선택, 사람이 읽을 수 있는 사용자 메타데이터
extensions/<vendor>/<name>/...   선택, 공급자 확장 데이터
```

경로는 `/` 구분자의 정규화된 UTF-8 상대 경로만 허용한다. 절대 경로, 드라이브 문자, `..`, 역슬래시, NUL, 심볼릭 링크와 중복 엔트리는 거부한다. 파일 이름은 의미 식별자로 사용하지 않고 UUID 또는 해시로만 연결한다.

### 매니페스트와 버전

`manifest.cbor`는 canonical CBOR로 기록하고 최소한 다음 필드를 가진다.

```text
format: "OctoPaint"
container_version: { major, minor }
document_id: UUID
document_entry: "document/document.cbor"
created_by: { application, application_version }
required_features: [string]
optional_features: [string]
minimum_reader: { major, minor }
```

- `major`가 더 크면 읽기를 중단한다. 의미를 안전하게 보존할 수 없는 호환성 변경에만 major를 올린다.
- 지원하는 major에서 더 큰 `minor`는 `required_features`를 모두 이해할 때만 연다. 모르는 필수 기능은 오류, 모르는 선택 기능은 경고 후 무시 또는 불투명 보존한다.
- 새 writer는 예전 파일을 메모리에서 단계적으로 마이그레이션한다. 사용자가 저장하기 전에는 원본 파일을 갱신하지 않는다.
- 객체 ID는 저장 사이에 안정적인 UUID다. 레이어 순서 변경이나 일부 편집이 모든 객체를 다시 쓰게 만들지 않는다.
- 숫자, 열거형, 색 공간과 블렌딩 모드는 문자열 추측 대신 버전이 지정된 타입 ID로 기록한다. CBOR 정수는 명세의 네트워크 바이트 순서를 따른다.

### 문서 그래프

`document/document.cbor`는 다음 정보를 가진다.

- 픽셀 크기, 해상도와 캔버스 원점
- 작업 색 공간, ICC 프로파일 참조, 채널 정밀도
- 루트 레이어 스택과 사용자 채널 목록
- 활성 선택 영역 객체 참조(선택적으로 저장)
- 안내선, 격자, 배경 표시 등 문서 범위 설정

각 `objects/<uuid>.cbor`는 `type`, `schema_version`, 공통 표시 속성, 자식 또는 입력 참조와 타입별 payload를 가진다. v1 객체 타입은 다음과 같다.

- 래스터 레이어와 레이어 그룹
- 픽셀 마스크 및 선택 영역 마스크
- 사용자 알파/스폿 채널
- 명도·대비, 색조·채도, 커브와 desaturate 조정 노드
- 클리핑 관계와 블렌딩 옵션

조정은 결과 픽셀이 아니라 파라미터, 적용 색 공간과 마스크 참조를 저장한다. 미지원 미래 객체는 생성 당시의 렌더 프록시를 함께 둘 수 있지만, 프록시는 권위 데이터가 아니다.

### 픽셀 타일

- 기본 타일 크기는 `256 x 256` 픽셀이며 가장자리 타일은 실제 폭과 높이를 기록한다.
- 래스터 레이어, 마스크 및 채널은 각각 타일 인덱스를 가진다. 인덱스는 `(x, y, mip)`에서 타일 digest를 참조한다.
- 완전히 투명하거나 일정한 타일은 인덱스의 상수 값으로 표현해 blob을 생략한다.
- 한 타일 blob은 `OCTT` 매직, 타일 스키마 버전, 폭/높이, 채널 수와 의미, 샘플 형식(`u8`, `u16`, `f16`, `f32`), 행 배치, 압축 방식, 압축 전 크기와 payload를 가진다.
- payload는 v1에서 무압축 또는 Zstandard를 사용한다. 디코더는 헤더의 예상 크기를 검증한 뒤 제한된 버퍼에만 푼다.
- 타일은 헤더와 payload 전체의 SHA-256으로 주소화한다. 동일한 내용은 파일 안에서 중복 저장하지 않는다.
- 캐시용 mip과 프리뷰는 삭제 후 재생성할 수 있으며 편집 원본으로 사용하지 않는다.
- GPU 텍스처 포맷은 디스크 포맷이 아니다. 로딩 시 코어 픽셀 표현에서 렌더러 리소스로 변환한다.

### 무결성

`integrity.cbor`는 자신을 제외한 모든 권위 엔트리에 대해 정규 경로, 압축 전 크기와 SHA-256을 기록한다. 정렬된 `(path, size, digest)` 목록의 SHA-256을 `root_digest`로 함께 기록한다.

- ZIP CRC는 빠른 손상 탐지에만 사용하고, 성공적으로 연 것으로 판정하려면 크기와 SHA-256도 확인한다.
- 참조된 객체와 타일이 모두 존재하는지, 참조 그래프에 금지된 순환이 없는지 검증한다.
- 프리뷰와 재생성 가능한 캐시는 무결성 목록에서 제외할 수 있다. 손상된 프리뷰는 무시하고 다시 만든다.
- SHA-256은 손상 탐지용이며 서명이 아니다. 출처 신뢰나 위변조 방지를 보장하지 않는다.
- 부분 복구 모드는 명시적 사용자 동의가 있을 때만 사용한다. 손실 객체를 투명 대체하여 별도의 새 문서로 열고 원본을 덮어쓰지 않는다.

### 원자 저장과 복구

1. 현재 문서 리비전의 불변 스냅샷을 잡는다.
2. 대상 파일과 같은 디렉터리에 충돌하지 않는 임시 파일을 만든다.
3. 새 컨테이너를 처음부터 작성하고 모든 필수 엔트리를 다시 읽어 크기, digest와 참조를 검증한다.
4. 임시 파일 핸들에 `FlushFileBuffers`를 수행한다.
5. 기존 대상이 있으면 `ReplaceFileW`로 교체하고, 없으면 같은 볼륨 안에서 원자적 rename을 사용한다. 선택 설정으로 직전 파일을 `.bak`에 보관할 수 있다.
6. 교체가 성공하고 저장한 리비전이 현재 리비전과 같을 때만 해당 문서의 dirty 플래그를 해제한다.

임시 파일은 예외, 취소 또는 검증 실패 시 삭제한다. 네트워크 공유나 원자 교체를 보장하지 않는 파일 시스템은 보장을 낮추고 UI에 경고한다. 자동 복구는 원본 옆 파일이 아니라 사용자별 로컬 복구 디렉터리에 문서 ID와 리비전으로 저장하며, 정상 저장 또는 명시적 폐기 후 정리한다.

## PNG 및 JPEG

### 가져오기

- PNG/JPEG 한 파일은 배경 없는 단일 래스터 레이어 문서로 연다.
- PNG의 알파, 8/16비트 채널, ICC/sRGB/gAMA 정보를 가능한 범위에서 읽는다. 팔레트와 회색조는 내부 작업 색 공간으로 명시적으로 변환한다.
- JPEG의 EXIF 방향은 픽셀에 적용한 뒤 방향을 1로 정규화한다. ICC, EXIF 해상도와 합리적인 메타데이터만 보존한다.
- 디코더가 축소 디코딩을 지원하더라도 편집 문서 생성에는 원래 해상도를 사용한다. 미리보기 경로에서만 축소 디코딩한다.

### 내보내기

- 모든 보이는 레이어, 마스크, 채널 영향과 조정을 문서 합성 규칙으로 렌더한 뒤 단일 이미지로 내보낸다.
- PNG는 RGB/RGBA 8비트와 16비트를 지원한다. 사용자 알파 채널 여러 개, 레이어, 선택 영역과 조정 파라미터는 저장하지 않는다.
- JPEG는 8비트 YCbCr/RGB 결과만 저장하며 알파가 없다. 투명 영역은 사용자가 지정한 matte 색과 합성한다. 지정하지 않으면 내보내기를 확인시키며 기본값은 흰색이다.
- JPEG 품질, 크로마 서브샘플링과 progressive 여부를 옵션으로 노출한다. 반복 JPEG 저장은 손실이 누적됨을 알린다.
- 내보내기는 문서의 원본 경로나 dirty 상태를 바꾸지 않는다. PNG/JPEG로 `Save`하려 하면 `.ocp` 저장 또는 평면화 `Export` 중 무엇인지 명확히 구분한다.

## PSD 읽기/쓰기 호환 정책

PSD 구현 기준은 Adobe의 공개 [Photoshop File Formats Specification](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)이다. PSD v1의 최대 치수는 30,000 x 30,000이고 채널 수는 최대 56이다. 더 큰 문서용 PSB v2는 초기 범위에 포함하지 않으며, 해당 문서는 `.ocp`로 저장하거나 사용자가 명시적으로 크기를 줄여야 한다.

### v1 호환성 매트릭스

| 기능 | PSD 읽기 | PSD 쓰기 | 정책 |
|---|---|---|---|
| RGB/회색조 8·16비트 | 지원 | 지원 | ICC 프로파일과 합성 이미지를 함께 기록 |
| RGB 32비트 부동소수 | 부분 지원 | 부분 지원 | 지원 연산만 유지하며 호환성 검사 후 경고 |
| CMYK/Lab/Indexed/Bitmap/Duotone | 색 변환하여 읽기 | 미지원 | 포함된 ICC 우선, 없으면 명시한 기본 프로파일 사용; 원 모드 왕복 보장 안 함 |
| 래스터 레이어, 순서, 이름, 표시, 불투명도 | 지원 | 지원 | 레이어 사각형과 채널 데이터를 보존 |
| 폴더/그룹 | 지원 | 지원 | 통과/격리 합성 차이를 검사 |
| 일반 블렌딩 모드 | 지원 | 지원 | 양쪽에 동일한 모드만 구조적으로 기록 |
| 미지원 블렌딩/고급 블렌딩/knockout | 렌더 프록시로 부분 지원 | 병합 또는 래스터화 | 저장 전 손실 경고 |
| 픽셀 레이어 마스크 | 지원 | 지원 | 밀도/feather 등 추가 속성은 지원 범위 밖이면 bake |
| 벡터 마스크 | 래스터화 | 래스터 마스크로 쓰기 | 경로 편집성 손실 |
| 사용자 알파 채널 | 지원 | 지원 | PSD 채널 한도 내에서만 저장 |
| 스폿/멀티채널 | 부분 지원 | 부분 지원 | 색/견본 의미는 손실 가능, 경고 필수 |
| 활성 선택 영역 | 알파/마스크로 가져오기 | 선택 알파 채널로 선택적 쓰기 | Photoshop의 활성 UI 상태 자체는 보장하지 않음 |
| Hue/Saturation, Curves 등 알려진 조정 레이어 | 부분 지원 | 부분 지원 | OctoPaint와 의미가 일치하는 파라미터만 매핑 |
| Desaturate 및 OctoPaint 전용 조정 | 렌더 결과 사용 | 래스터화 | 동등한 PSD 조정 레코드가 없으면 편집성 손실 |
| 텍스트, 도형 | 보이는 결과로 가져오기 | 래스터 레이어 | 글꼴·벡터 편집성 손실 |
| 스마트 오브젝트/스마트 필터 | 보이는 결과로 가져오기 | 래스터 레이어 | 내장 원본과 비파괴 필터 편집성 손실 |
| 레이어 효과 | 부분 렌더 | 래스터화 또는 효과 bake | 효과 파라미터 왕복 보장 안 함 |
| 메타데이터/ICC/해상도 | 허용 목록 기반 지원 | 지원 항목만 쓰기 | 실행 가능하거나 비정상적으로 큰 블록은 제외 |

“지원”은 OctoPaint가 정의한 골든 파일 집합에서 픽셀 의미와 편집 구조를 보존한다는 뜻이지, 모든 Photoshop 버전과 플러그인의 비공개 데이터를 보존한다는 뜻은 아니다.

### PSD 가져오기 규칙

- PSD의 길이 필드를 신뢰하지 않고 상위 섹션 경계, 파일 크기와 산술 오버플로를 함께 검증한다. PSD 수치는 big-endian으로 읽는다.
- 레이어 구조와 별도로 저장된 composite image를 먼저 안전하게 디코딩한다. 이해하지 못한 레이어 기능은 composite 또는 해당 레이어의 렌더 프록시로 시각적 폴백을 제공한다.
- 미지원 리소스 블록은 크기 제한 아래에서 불투명 원본 데이터로 보관할 수 있다. 단, 원본 노드가 수정되지 않았고 블록의 내부 참조가 검증된 경우에만 PSD 재내보내기에 통과시킨다.
- 색상 모드 변환, 래스터화, 누락된 글꼴/프로파일, 잘린 채널 및 무시한 블록을 가져오기 보고서에 남긴다.
- PSD를 연 문서도 최초 상태부터 OctoPaint 문서 모델이다. PSD 원본을 자동으로 덮어쓰지 않으며 기본 저장 대상은 `.ocp`로 제안한다.

### PSD 내보내기 규칙

- 내보내기 전에 문서 전체를 dry-run하여 `호환`, `부분 손실`, `평면화 필요`, `내보내기 불가`로 분류한다.
- 가능한 노드는 PSD 레이어/마스크/조정 레코드로 기록한다. 의미가 다른 노드는 원본을 숨겨 끼워 넣지 않고, 사용자가 선택한 범위에서 래스터화하거나 병합한다.
- 항상 현재 OctoPaint 렌더 결과의 composite image를 함께 기록한다. 다른 뷰어가 확장 레코드를 이해하지 못해도 합성 결과를 표시할 수 있어야 한다.
- PSD 한도를 넘는 크기, 채널 수 또는 표현 불가능한 정밀도는 조용히 자르지 않고 실패시킨다.
- 지원하지 않는 기능이 있으면 기본 동작은 사용자에게 손실 보고서를 보여주는 것이다. 사용자가 승인한 경우에만 복사본으로 내보내며 `.ocp` 원본은 유지한다.
- 결과 파일을 다시 OctoPaint PSD 디코더로 열어 구조 검사를 통과한 뒤 대상 경로에 원자 교체한다.

### 피할 수 없는 손실 사례

- OctoPaint와 Photoshop의 합성 수학, 색 관리, 감마 및 반올림 차이로 경계 픽셀이 달라질 수 있다.
- Photoshop 비공개 추가 레이어 정보, 플러그인 데이터, 스마트 오브젝트와 일부 효과는 완전한 의미를 알 수 없다.
- 벡터/텍스트를 래스터화하면 확대 편집성과 원 파라미터가 사라진다.
- 32비트 HDR, CMYK/Lab, 스폿 색상은 RGB 중심 작업 문서와 변환할 때 gamut과 채널 의미가 달라질 수 있다.
- OctoPaint 전용 블렌딩 또는 조정은 PSD 대응 기능이 없으면 병합 결과만 전달할 수 있다.

## 오류 모델과 사용자 경험

오류는 최소한 다음 코드로 구분한다.

- `UnrecognizedFormat`, `UnsupportedVersion`, `UnsupportedRequiredFeature`
- `CorruptContainer`, `IntegrityMismatch`, `TruncatedData`, `InvalidReference`
- `LimitExceeded`, `DecompressionLimitExceeded`, `ColorProfileRejected`
- `PermissionDenied`, `DiskFull`, `TargetBusy`, `AtomicReplaceUnavailable`
- `Cancelled`, `ExportWouldLoseData`, `CodecFailure`

오류에는 안전하게 표시할 파일명, 단계, 복구 가능 여부와 기술 진단 ID를 포함하되, 임의 파일 내용이나 전체 경로를 원격 로그로 보내지 않는다. 실패한 열기는 빈 탭이나 반쯤 구성된 문서를 만들지 않는다. 실패한 저장은 기존 파일과 dirty 상태를 그대로 유지한다. 오류 메시지에는 원본 보존 여부와 임시/복구 파일 위치를 명확히 알린다.

## 보안 및 자원 제한

제한값은 정책 객체로 주입하고 단위 테스트에서는 축소할 수 있다. 데스크톱 기본값은 실제 하드웨어 예산과 제품 검증 후 확정하되 다음 항목은 반드시 제한한다.

- 캔버스 폭/높이, 총 픽셀 수, 레이어·그룹 깊이, 채널 및 객체 수
- 단일 엔트리와 전체 압축 해제 크기, 압축률, ZIP 엔트리 수
- 타일 개수, 타일의 압축 전 크기, ICC/EXIF/XMP 및 불투명 확장 블록 크기
- PSD 섹션 길이, RLE 행 길이 합계, 중첩/참조 깊이와 문자열 길이
- 열기/내보내기 시간, CPU 작업량, 동시 디코드 수와 GPU 업로드 예산

모든 크기 계산은 checked 64비트 산술을 사용하고 할당 전에 상한을 검사한다. 압축 해제는 스트리밍하며 선언 크기와 실제 출력 크기가 다르면 중단한다. ICC 프로파일은 OS 색 관리 API 또는 격리된 검증 경로에서 처리한다. 미리보기 생성과 PSD/이미지 디코딩은 취소 가능한 작업 큐에서 실행하고, 파서 입력으로 셸 명령, DLL 로드, 외부 URL 접근 또는 상대 경로 파일 접근을 수행하지 않는다.

## 테스트 전략

### `.ocp`

- 최소 문서, 깊은 그룹, 빈/상수/가장자리 타일, 각 정밀도와 채널 구성의 골든 파일을 버전별로 유지한다.
- `encode -> decode -> encode` 후 문서 그래프와 권위 타일 digest가 동일한지 검사한다. ZIP 엔트리 순서나 타임스탬프는 의미 비교에서 제외한다.
- manifest/object/tile의 한 바이트 변조, 누락, 중복 경로, 잘못된 digest, 순환 참조와 ZIP bomb를 주입해 거부되는지 검사한다.
- 저장 각 단계에 fault injection을 넣어 취소, 디스크 부족, 프로세스 종료와 교체 실패 뒤에도 기존 파일 또는 검증된 새 파일 중 하나만 남는지 검사한다.
- 이전 minor/major 샘플을 보관하고 마이그레이션 및 `required_features` 협상을 회귀 테스트한다.
- 큰 파일은 전체 픽셀을 메모리에 올리지 않고 필요한 타일만 읽는지 메모리 상한과 I/O 계측으로 검증한다.

### PNG/JPEG

- PNG 팔레트/회색/RGB/RGBA, 8/16비트, ICC와 투명도 조합을 골든 이미지로 비교한다.
- JPEG 방향, ICC, subsampling과 손상된 marker corpus를 테스트한다.
- PNG는 무손실 픽셀 비교, JPEG는 지정 품질별 허용 오차 또는 SSIM 기준으로 비교한다.
- 알파 matte, 색 변환과 메타데이터 제외가 `ExportReport`에 정확히 기록되는지 검사한다.

### PSD

- Adobe 명세의 구조 변형과 Photoshop에서 생성한 허용 가능한 골든 파일을 8/16/32비트 및 레이어 기능별로 유지한다.
- OctoPaint가 쓴 PSD를 OctoPaint에서 다시 읽는 구조 테스트와, 지원하는 Photoshop 버전에서 열고 다시 저장하는 상호운용 테스트를 자동/수동 릴리스 게이트로 둔다.
- 기능별 호환성 매트릭스 각 행에 최소 하나의 왕복 샘플과 예상 손실 보고서를 둔다.
- composite와 OctoPaint 기준 렌더를 색 관리 조건을 고정한 이미지 diff로 비교한다. 허용 오차는 기능과 정밀도별로 명문화한다.
- 절단 파일, 잘못된 길이, 정수 오버플로, 과도한 RLE, 중복 리소스, 깊은 레이어 트리를 fuzzing과 sanitizer 빌드로 지속 검사한다.

## 단계적 제공 범위

1. `.ocp` v1 읽기/원자 저장, PNG/JPEG 읽기/내보내기, 손상 및 제한 테스트를 먼저 완성한다.
2. PSD RGB 8/16비트, 래스터 레이어·그룹·픽셀 마스크·일반 블렌딩·알파 채널과 composite를 제공한다.
3. Curves와 Hue/Saturation 등 검증된 조정 매핑, 32비트 부분 지원과 고급 메타데이터를 추가한다.
4. 각 기능은 호환성 매트릭스, 손실 보고서와 외부 상호운용 골든 테스트가 함께 준비된 경우에만 “지원”으로 승격한다.
